Mining Telemetry Dataset
1. Overview
This dataset contains high-frequency telemetry data for mining equipment, primarily dumpers. Each record represents a timestamped observation capturing vehicle movement, fuel levels, and device signals.

The data has been anonymized while preserving spatial and operational characteristics. It is intended for use in developing fuel consumption models and operational analytics.

Data frequency is typically between 10 and 60 seconds
Each row corresponds to a single telemetry observation
The dataset includes both raw sensor signals and processed fields
2. Prediction Goal
The primary objective is to build a model that can predict the total daily fuel consumption for each vehicle. This involves using high-frequency telemetry data to forecast aggregated daily metrics.

The model should also be able to predict other daily performance indicators, such as:

Production Hours
Idle Hours
Distance Traveled (KM)
Total Tonnage Hauled
3. Training Set (df)
The training set contains high-frequency telemetry data for a specific period and is designed to be used for model development.

Content: It includes detailed sensor readings (speed, altitude, ignition, etc.) and location data.
Target Variables: This dataset contains the aggregated daily production report (DPR) values, which serve as the ground truth for training. These include fuel_volume, prod_hr_dpr, idle_hr_dpr, maint_hr_dpr, bd_hr_dpr, hmr_dpr, km_dpr, and tonnage.
The training set contains 4,334,181 rows and 39 columns, using approximately 1.1 GB of memory.

4. Test Set (df_test)
The test set contains telemetry data from a different time period and is used to evaluate the performance of the trained model on unseen data.

Content: It has the same high-frequency telemetry features as the training set (e.g., speed, altitude, ignition).
Unavailable Columns: To simulate a real-world prediction scenario, the following columns (the target variables) have been removed from the test set: fuel_volume, prod_hr_dpr, idle_hr_dpr, maint_hr_dpr, bd_hr_dpr, hmr_dpr, km_dpr, and tonnage.
Your task is to use the features available in the test set to predict these missing daily values.

5. Column Reference
5.1 Time Fields
Column	Dtype	Description
ts	datetime64[us, Asia/Kolkata]	Timestamp of the telemetry event (device time)
received_ts	datetime64[us, Asia/Kolkata]	Timestamp when the data was received on the server
Use ts as the primary timestamp for analysis. received_ts can be used to assess data latency or transmission delays.

5.2 Location & Spatial Fields
Column	Dtype	Description
latitude	float64	Latitude (anonymized, WGS84)
longitude	float64	Longitude (anonymized, WGS84)
altitude	int32	Elevation in metres
Coordinates are aligned with the anonymized mine maps provided separately. Use these fields for route mapping, distance computation, and terrain analysis.

5.3 Equipment Identity
Column	Dtype	Description
vehicle	str	Anonymized vehicle identifier (e.g., Dump001)
mine_anon	str	Anonymized mine identifier (e.g., mine001)
Vehicle names are deterministic and consistent across the dataset. Mine identifiers correspond to the anonymized spatial files.

5.4 Movement & Behaviour
Column	Dtype	Description
speed	float64	Speed in km/h
ignition	int32	Engine status (1 = ON, 0 = OFF)
angle	int32	Heading direction in degrees (clockwise from North)
Speed of zero with ignition ON typically indicates idling. Use these fields to determine movement, idle periods, and direction of travel.

5.5 Fuel Data
Column	Dtype	Description
fuel_volume	float64	Primary field. Final calibrated fuel balance (volume remaining in tank)
Use fuel_volume as the primary fuel variable. Fuel signals may be noisy and should be smoothed or aggregated before analysis. This is also a target variable (removed from the test set).

5.6 Signal Quality Indicators
Column	Dtype	Description
satellites	int32	Number of GPS satellites in use
gnss_pdop	int32	Position dilution of precision (lower = better accuracy)
gnss_hdop	float64	Horizontal dilution of precision (lower = better accuracy)
gsm_signal	int32	GSM signal strength
gsm_operator	int32	Network operator identifier
These fields can be used to filter unreliable GPS points.

5.7 Device & Electrical Signals
Column	Dtype	Description
battery_level	float64	Device battery percentage
battery_current	int32	Current draw
battery_voltage	int32	Internal battery voltage
external_voltage	int32	Vehicle power supply voltage
5.8 Motion Sensors
Column	Dtype	Description
axis_x	float64	Accelerometer reading — X axis
axis_y	float64	Accelerometer reading — Y axis
axis_z	float64	Accelerometer reading — Z axis
Can be used for advanced analysis such as vibration detection or driving behaviour profiling.

5.9 Additional Signals
Column	Dtype	Description
analog_input_1	float64	Auxiliary analog input carrying the dump switch signal for some dumpers. Values range from 0.1 to 4 V — a max dump body tilt (80°) generates ~4 V. Any value above 2.5 V is considered a dump event.
5.10 Distance Metrics
Column	Dtype	Description
disthav	float64	Incremental Haversine-based distance in metres
cumdist	float64	Cumulative distance in kilometres
Pre-calculated incremental and cumulative distances with independent counters per vehicle.

5.11 Daily Production Report (DPR) Fields
These fields are aggregated daily values from the production report. They are available in the training set only and serve as the target variables for prediction.

Column	Dtype	Description
shift_dpr	category	Shift identifier from the daily production report
date_dpr	object	Date of the production report entry
operator_id	float64	Operator identifier
hmr_dpr	float64	Hour meter reading from the DPR
prod_hr_dpr	float64	Production hours
idle_hr_dpr	float64	Idle hours
maint_hr_dpr	float64	Maintenance hours
bd_hr_dpr	float64	Breakdown hours
km_dpr	float64	Distance traveled (km)
total_trip	float64	Total number of trips
tonnage	float64	Total tonnage hauled
rain_loss	float64	Hours lost to rain
dense_fog	float64	Hours lost to dense fog

7. Spatial Map Data
7.1 Overview
All maps were anonymized using a consistent spatial transformation that preserved geometry, topology, and relative distances. Each file is a GeoPackage (.gpkg) containing multiple spatial layers.

Since the anonymization is a pure spatial translation, models and algorithms developed on this data can be directly applied to the original data without modification.

7.2 Layers
Each GeoPackage may contain the following layers:

Layer	Description
haul_road	Haul road network (LineStrings)
bench	Bench geometries
ob_dump	Overburden dump areas
stock / mineral_stock	Intermediate and ROM stockpile areas
ml_boundary	Mine boundary
nh_road / village_road	External/reference roads
cpu	Crushing plant
office	Infrastructure areas
7.3 Map Structure
All primary spatial layers are in a projected coordinate system — UTM (EPSG:32645), units in metres. Haul roads are represented as line geometries (no explicit road IDs are provided). Geofences (load/dump areas) are represented as line boundaries, not filled polygons.

Participants are expected to derive route structure from haul roads, define zones from geofences, and build spatial relationships using these layers.

8. Coordinate System
Dataset	CRS	Units
Telemetry (latitude, longitude)	WGS84 — EPSG:4326	Degrees
Spatial map layers	UTM — EPSG:32645	Metres
Telemetry data must be converted to EPSG:32645 before performing any spatial analysis.

9. Data Characteristics & Considerations
GPS Noise — Minor deviations from haul roads are expected. Filtering or map-matching may be required.

Fuel Signal Variability — Fuel levels may fluctuate due to sensor noise and vehicle movement. Consumption should be calculated over stable intervals.

Time Gaps — Data may not be uniformly sampled. Missing intervals should be handled appropriately.

Multiple Fuel Sources — Additional analog fuel sensor readings should be ignored. Use the fuel_volume field as the primary source. Vehicles without fuel sensors will not contain this information.

10. Recommended Initial Steps
Clean and validate telemetry data
Convert coordinates to the map projection system (EPSG:32645)
Identify moving and idle segments
Map telemetry points to haul roads and zones
Segment haul cycles
Compute fuel consumption over cycles or time windows
Aggregate features to a daily level per vehicle
Train models using DPR target variables
Predict targets on the test set
